# 实验代码与复现指南

固定解释器：`E:\anconda\envs\py310\python.exe`。在本文件所在目录打开PowerShell执行以下命令。依赖版本见`requirements_locked.txt`，环境记录见`environment_capture.json`。未创建新虚拟环境或修改当前环境。

## 1. 推荐先运行的命令

| 命令参数 | 实际工作 | 是否需要原始栅格 | 本轮验证 |
| --- | --- | --- | --- |
| `verify` | 从冻结逐条件结果重新生成均值、区间、交互对比和因素贡献 | 否 | 通过 |
| `cached` | 从充分统计缓存重新拟合v4开发模型／选择器、生成候选预测，重新校准并预测v5 | 否 | 通过 |
| `selection` | 从候选表重建40测试窗、36补充开发窗及63外推窗的位置选择 | 否 | 名单一致 |
| `preflight` | 检查6个栅格的路径、尺寸、格网和CRS；核对一个窗口两期两个偏移的原始面积直方图与缓存 | 是 | 通过 |
| `raw-selection` | 重扫完整栅格候选池并重选原24个机制窗 | 是 | 本轮未完整运行 |
| `raw-mechanism` | 在冻结样区上重跑原机制运算及三尺度九相位，并重新统计 | 是 | 本轮未完整运行 |
| `raw-cross` | 从原始4输入重新提取v4／v5匹配统计，拟合、校准、预测、生成影像和评价 | 是 | 本轮未完整运行 |

```powershell
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py verify
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py cached
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py selection
```

每次命令都会创建新的运行目录，不会复用上次目录。执行完成后查看该目录的`REPRODUCTION_CHECK.json`，只有`status: PASS`表示本次比较通过。`*.log`保留每个阶段的完整输出。快照执行前后均检查SHA256；如果你想修改方法，应在新的研究副本中进行，不要直接改动快照后仍称为原结果复现。

缓存复算已逐项比较v4开发折结果、选择记录、1120项候选预测，以及v5参数校准和21630项预测；它不重新读取每个像元计算变化F1。变化F1的统计核验使用已冻结逐事件表，完整像元重算使用`raw-cross`。

## 3. 原始栅格重算

首先检查`input_paths.json`中的6个路径：Han2000、2010、2015、2020，以及Wang2010、2020。文件不在压缩包内。换电脑只修改这里的栅格路径，保持所用数据版本不变；不能用名称相同但内容不同的产品替代后仍沿用原结论。

```powershell
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py preflight
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py raw-selection
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py raw-mechanism
& 'E:\anconda\envs\py310\python.exe' -B .\reproduce.py raw-cross
```

`raw-selection`与`raw-mechanism`是独立运行：前者检验候选扫描与原24窗选择；后者直接使用冻结样区重算。`raw-cross`也使用冻结的60／40／63窗，选区规则另由`selection`核验。新结果与冻结对应表逐项比较，预测影像位于各自新目录的`outputs/`。

完整原始栅格运行会生成缓存、NPZ或GeoTIFF，耗时和磁盘占用明显高于前面的轻量核验。本轮只做了原始读取预检与单窗核对，没有声称全部原始栅格重算已再次完成。

## 4. 原始代码版本与依赖

| 快照目录 | 内容 | 当前论文用途 |
| --- | --- | --- |
| `snapshots/mechanism/` | 原始选区、core.py、experiments.py、统计及九相位代码；冻结参数、候选表与结果 | 24窗多维响应及非交换性／支持域实验 |
| `snapshots/v4/` | engine.py、run.py、finish.py；60／40窗、空间折、选择器及匹配缓存 | 先行跨产品选择、后续消融复用的开发基础；选择结果保留在补充材料 |
| `snapshots/v5/` | ablation.py、report.py、四组约束消融、63窗外推、参数及结果 | 当前4.5.4及图4.8、S1、S2的主要定量依据 |
| `snapshots/selection_history/` | v3几何可行性与v4输入预检／设计文件 | 追溯36、40、63窗的来源；不把v3方案当作已执行v5 |
| `snapshots/manuscript_analysis/` | 贡献分解、原始绘图和正文生成代码 | 图件与论文派生分析的来源 |

**不要依次执行快照内所有脚本。**原始机制脚本还保留了旧实验3分支，完整调用会在新目录产生这些历史辅助结果，以维持原统计执行顺序；它们不属于当前v5框架效果验证。不要把旧面积守恒、旧评分或旧p值混入当前结论。

运行副本只做两类可追踪适配：`core.inputs()`从配置读取栅格路径；v5报告移除指向旧电脑目录的元数据检查，改由包级SHA256与预检负责。算法和统计函数保留，适配前后哈希记入每次运行的`portability_adaptations.json`。冻结参数中只更新路径及文件元数据，方法参数不变。
